# 每日签到面板（详细手册）

跑在 Cloudflare Workers 上的自动签到面板：**网页后台管账号 + D1 存数据 + 每天定时签到 + 推送通知**。
零依赖，一个 Worker 加一个浏览器扩展（负责抓 Cookie，以及用你家的网络代发请求）。

**开源共建**：站点适配谁都能贡献 —— 在面板里把签到调通，导出成一段 JSON 发过来，
别人导入就能用，不用改代码、不用重新部署。见 [社区站点适配](#社区站点适配不写代码也能加站点)。

---

## 先看这里：3 个最容易踩的坑

| 坑 | 后果 | 怎么办 |
|---|---|---|
| `wrangler.toml` 里的 `database_id` 没换成自己的 | 连不上数据库，面板打不开 | 见 [部署](#部署两条路) |
| 又把 `EXTERNAL_API_KEY` 设成 Worker Secret | 它优先级**高于**面板里生成的 Key，会出现「复制了 Key，扩展却连不上」 | **不要设它** |
| 换域名 / 更新面板后没管扩展 | 扩展还在连旧地址、还是旧代码 | 换域名去扩展弹窗改地址；面板更新后**重新下载并加载一次扩展** |

## 它是什么

| 能力 | 说明 |
|---|---|
| 多账号管理 | 增删改、启用/停用、单个或全部手动执行 |
| 定时自动签到 | 每天指定时间（精确到分钟）自动跑，支持时区，每个账号可单独设时间 |
| 一键加账号 | 扩展「一键复制全部信息」→ 面板粘贴 → 自动认站点、填 Cookie 和 UA、试跑 |
| 面板能真签到（需浏览器的站） | 吾爱破解这类只能由浏览器亲自签的站：面板把登录态交给扩展写回浏览器 → 打开首页 → 点站点自己的打卡入口 → 回首页核对，**全自动** |
| 状态一定对得上站点 | 报成功前先回首页核对（首页那个打卡入口才是服务端状态，结果页文案不算数）；对不上就如实报「没签上」，读不清注明「未能复查」 |
| 本地网络执行 | 扩展代发请求，用你家的 IP + 你的 Cookie，绕过机房 IP 被拦 |
| 万能「自定义 HTTP」 | 抓一次 cURL 就能接入任意网站，支持多步（先登录拿 token 再签到） |
| 网络连接状态 | 全局签到卡右侧一行：阿里 / 谷歌 / Facebook / GitHub / Telegram / 百度逐个探一遍，一眼看出是「面板出口不通」还是「某个站点自己的问题」 |
| 推送通知 | Telegram / Bark / 通用 Webhook 推签到日报 |

> 架构一句话：**Cloudflare 负责「什么时候跑、跑哪个账号、怎么判成功」，扩展负责「用你的网络和 Cookie 把请求发出去」。**

## 部署：三条路

**推荐走这条（纯网页，不装任何东西）**：Fork 仓库 → Cloudflare 建同名 D1 → 把 `database_id` 填回 fork →
**导入存储库**建 Worker → 设 `ENCRYPT_KEY` Secret。每一步点什么按钮、填什么，
[README](../README.md) 的「部署到 Cloudflare」一节是逐步截图级的说明，这里不重复。

**命令行一键**（电脑上装了 Node.js 的话最快）：在项目目录里跑

```bash
node deploy.mjs          # 建库、设密钥、部署、当场验收，全程中文提示
node deploy.mjs --check  # 只体检不发布：检查登录状态、database_id、密钥是否齐
```

**要手动一步步来**（或想知道每一步在干什么）：

```bash
npx wrangler@latest login                                # ① 登录（浏览器点「允许」）
npx wrangler@latest d1 create daily-checkin-panel        # ② 建库，记下输出里的 database_id
#    → 把 database_id 填进 wrangler.toml（binding = "DB" 不要改；仓库自带的是作者的库）
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
npx wrangler@latest secret put ENCRYPT_KEY               # ③ 粘上面那串（不设也能用，但建议固定）
npx wrangler@latest deploy                               # ④ 部署，打印你的面板地址
```

- 命令一律写 `npx wrangler@latest`。**不要**直接写 `wrangler`，老版本不支持本项目的静态资源配置。
- 网页部署（导入存储库）的路径里没有命令行，上面这几条命令只属于命令行路线；
  网页路线设密钥在 Worker 的「设置 → 变量和密钥」里点出来（见 README）。
- 表结构不用手动建：第一次打开面板自动建表，升级代码时自动加列（不删数据）。
- 报错 `database with name ... already exists`：说明建过了，跑 `npx wrangler@latest d1 list` 找 id 填进 `wrangler.toml`。
- `ENCRYPT_KEY` 必须是**正好 32 字节的 base64**（上面的命令生成的就是），否则面板会直接报错。
- 变量名、绑定名、每一项填什么，[Cloudflare 部署清单](Cloudflare部署清单.md) 里是一张表。

### 部署完 4 件事

1. **打开面板设置管理密码**（至少 8 位）。密码用 PBKDF2-SHA256 加盐哈希存 D1，**忘了没法找回**。
   真忘了：`npx wrangler@latest d1 execute daily-checkin-panel --remote --command "DELETE FROM settings WHERE key='admin_hash'"` 后重新走一次设置。
2. **生成扩展 API Key**：设置 →「🔌 浏览器扩展」→ **🎲 重新生成 API Key**。
   这串 Key **只在生成那一刻显示一次**（之后只显示头尾几位），立刻复制到扩展弹窗里；忘了就再生成一把（旧的马上失效）。
3. **装浏览器扩展**：同一张卡点 **⬇️ 下载 签到面板助手** → 解压到固定文件夹（**别删、别移动**）
   → `chrome://extensions` 打开开发者模式 →「加载已解压的扩展程序」选那个**文件夹本身**
   → 点 🍪 图标填 API Key → **🔌 面板连接检查**显示「连接正常」即可。
   下载包里**已经自动写好了你现在的面板地址**（地址栏直接访问 `https://你的域名/checkin-helper.zip` 也行），不用手抄。
4. **加第一个账号**：在目标网站**手动登录** → 停在该网站页面上，点扩展 **📋 一键复制全部信息（含 UA）**
   → 面板「添加 / 更新账号」→「📋 粘贴即保存」里粘贴 → 面板自动认站点、填 Cookie/UA、试跑一次。

> 扩展按钮 `一键发送到签到面板` 走的是**一次性交接码**：内容先 POST 给面板，地址里只有一个 16 位短码
> （5 分钟有效、取一次作废），所以**整包 Cookie 不会进地址栏和浏览历史**。

### 绑定自定义域名（强烈建议）

`*.workers.dev` 在国内经常不稳定 —— 后果是你打不开面板、**扩展连不上面板**（于是所有走本地网络的账号都被跳过）。
把域名托管到 Cloudflare → Workers 控制台 → 你的 Worker → **设置 → 域和路由 → 自定义域**。
换完记得**去扩展弹窗改「签到面板地址」**。

## 日常使用

| 我想…… | 怎么做 |
|---|---|
| 马上签一次 / 全部签 | 那一行点 **执行** / 右上角 **全部执行** |
| 改签到时间 | 账号页「全局签到」：点 `每天 08:05`、`时区 中国台湾 · 台北` 两个胶囊，**选好即自动保存**（改完立即生效，不用重新部署；右边「💡 说明」悬浮看完整说明） |
| 给某个账号单独设时间 | 表格「全局签到」列点一下，选「跟随全局」就回到全局时间 |
| 暂时不签某个账号 | 那一行的开关关掉 |
| 看每次签的结果 / 网站原话 | 页面顶部 **运行日志**（可按账号/结果筛选，最近 500 条） |
| 看今天签了几个 | 表格「状态」列 + 汇总行 |

**账号页是三张卡**：签到账号（表格）→ 全局签到（一行）→ 添加 / 更新账号（粘贴区 + Cookie 解析器两个标签）。

- 「粘贴」和「解析」都在贴一大串 Cookie，所以合成了一张卡的两个标签、一栏到底；粘贴内容再长也是**限高 + 内部滚动**，不会把页面拉长。
- 浏览器扩展不在这儿：装一次以后几乎不再点，所以下载 / 安装步骤 / API Key 全集中到**设置页**那一张卡。

**状态徽章**（按你设的时区算「今天」，过当地 00:00 自动全部回到「未签到」，当天真签成功才变 ✅）：

| 显示 | 意思 |
|---|---|
| ✅ 已签到 | 今天真的签好了（或站点明确回「今日已签到」） |
| 🔴 未签到 | 还没签上；跳过和失败都不会让它变成已签到 |
| ⏭️ 跳过 | 这次没跑（如需要本地网络但扩展不在线），不算失败，也不覆盖上次结果 |

**网站反馈**列显示的是网站自己的原话，失败时下面跟一枚「💡 建议」胶囊 —— 正文默认不显示
（十行建议会把表格撑得又高又花），**鼠标移上去**才弹完整内容。

**鼠标移到站点名上**（名字下有虚线在提示你）会弹出这份凭据的**到期时间**：WordPress 系站点列出每个登录会话的
用户名与到期日、Akile 这类显示 `akile-token` 的过期时间；凭据里**没写**到期时间的站点会直说「没有写到期时间」
—— 面板**不猜**（拿它判断「要不要现在去重新登录」时，猜错比不说更坏）。它只读你自己加密存着的凭据，不下发 Cookie 原文。

**右上角「扩展在线」胶囊**：🟢 扩展在接单（可以切「本地网络」）；⚪ 离线时点它可立即重测，
此状态下**不允许**把账号切到本地网络（面板会直接拒绝并说明原因）。每 30 秒自动重测一次。

## 执行模式：云端 / 本地网络

| 徽章 | 含义 | 适合 |
|---|---|---|
| ☁️ CF 网络 | Cloudflare 机房 IP 直接发请求 | 普通 API 类站点（机场、Akile、天翼云盘、糊涂鳄…） |
| 🌐 本地网络 | 请求**经由你的浏览器扩展**发出，用你家的 IP + 登录态 | 会拦机房 IP 的站点（吾爱破解、NodeSeek…） |

**自动选路**（不动它就一直是自动）：① 先走上次真正走通的那条（徽章上写着「自动 · CF 网络」）；
② 没记录时按站点默认；③ 走不通就自动换另一条，换过会写进「网站反馈」。
「走不通」只认网络层原因（连不上、超时、机房 IP 被拦）；站点已经明确回答过的事（Cookie 失效、要人机验证）不会换条路重打。

- 扩展**离线**时，只能走本地网络的账号记为 ⏭️ 跳过，不会瞎报失败；能从 CF 直连的照签。
- 面板判断「扩展在线」的依据：**最近 90 秒内有扩展来领过任务**（扩展 15 秒长轮询，所以点「执行」通常 1 秒内就被领走）。
- 手动点「切换」会**固定**路线（徽章不再带「自动」），面板不再替你换。

> 为什么要有自动选路：糊涂鳄从 CF 直连实测完全正常，但旧版「扩展在线就一律走本地中继」，
> 中继是单飞执行，前面吾爱破解的浏览器工单占掉近一分钟，糊涂鳄就被挤成「中继超时」——
> 面板记失败，网站其实早签好了，也就是「面板跟网站对不上」。

## 社区站点适配：不写代码也能加站点

- **内置站点**：`src/sites/` 里的代码模块（上表），要改代码才能加。
- **社区站点**：一段 JSON（怎么发请求、怎么判成功），存进 D1，**导入后立刻生效，不用重新部署**。

**用别人的配置（30 秒）**：设置 → **🌍 社区站点（开源共享）** → 粘 raw 链接或 JSON 全文
→ **🔎 校验预览**（会说清是什么站、要填哪些字段、几步请求、有没有夹带凭据）→ **⬇️ 导入**。
之后「添加账号」里就能选到它（带 🌍 社区 标记）。仓库 `community/sites/` 里有现成配置，索引在 `community/index.json`。

**把自己调通的站分享出去**：用「自定义 HTTP」多步录制调通 → 设置页那张卡右侧「导出我的配置」
→ **选这个网站** → **📤 导出为社区配置**。

- 选的是**签到网站**、不是账号：要分享的是「这个网站怎么签」，别人导入后看到的也是网站名。
  一个站下挂了多个账号时，面板会自己挑那个录过任务的。
- 面板自动把真实 Cookie / token 换成 `{{cookie}}` 占位符、把你的域名换成 `{{site_url}}`，
  再倒推出「别人要填哪些字段」。
- 带凭据的配置**导不出去、也导不进来**：导出时清洗，导入时校验器直接拒绝明文 Cookie。

字段规范、PR 检查清单、示例见 [CONTRIBUTING.md](../CONTRIBUTING.md) 与 [community/README.md](../community/README.md)。

## Cookie 自动续命（会话轮换回写）

alist 这类网盘工具对 token 的做法是：请求过程中令牌被服务端轮换，就把新令牌**当场写回存储**，
而不是等它过期后人工重新填。面板的浏览器签到用的是同一套思路：

- 扩展用面板下发的登录态签完到后，会顺手读一遍浏览器里这个域名的登录 Cookie
  （auth / session / token 类），与下发值比对：**值变了 = 站点轮换了会话**，
  就把新值回写面板，凭据自动续命，不用过几天再人工重抓。
- 没变化就一个请求都不发；回写只换提交的那几条 Cookie，**UA 等其他凭据字段一律不动**。
- 面板端再做两道校验：回写域必须与账号站点同域、内容必须认得出登录名 —— 一把被偷的 API Key
  拿别的站的 Cookie 也污染不了你的账号。
- 每次回写都在账号 meta 里记 `cred_rotated_at` 时间戳；凭据哪天出问题，能看出它被自动续过命。
- 只覆盖「浏览器签到 + 注入凭据」的站点（吾爱破解这类）；服务端直签的站点不走浏览器，
  不产生轮换，也不需要它。

**服务端直签**走另一条同思路的续命：站点签到成功后，如果响应 `Set-Cookie` 里带回了
轮换后的新 Cookie，站点模块把它装进 `res.cookieRefresh`（`"a=1; b=2"` 格式）带回来，
执行引擎就地合并进账号凭据、加密存回 D1 —— 下次签到直接用新的，不用人工重抓。
只有**签到成功**时才回写（失败时的 Set-Cookie 可能是登出态，合进去会污染好凭据）；
回写失败只记进日志 detail，不影响本次签到结论。目前已接入：自定义 HTTP（含社区站点，
引擎自动收集各步骤的 Set-Cookie）、V2EX。自己写站点模块时，签到成功后顺手
`cookiesFrom(res)` 收集一下、通过 `cookieRefresh` 返回即可（见 `src/lib/web.js`）。

## 手动取 Cookie（不装扩展时的备用）

都在「添加 / 更新账号」→ 展开「🛠 不装扩展时的手动方式」里：

| 方式 | 怎么做 | 注意 |
|---|---|---|
| **请求头**（推荐） | F12 → 网络 → 任一请求 → 复制请求头整段 | Cookie 与 UA 会一起提取，吾爱这类要求配对的站最省事 |
| cURL 命令 | F12 → 网络 → 右键请求 → 复制为 cURL | 同样带出 UA |
| 小书签 / 地址栏代码 / 控制台 | 面板生成代码 → 拖到书签栏或粘到手机地址栏、Console | **读不到 HttpOnly Cookie**，NodeSeek 这类不行 |
| Cookie-Editor JSON / cookie.txt | 插件导出或抓包工具导出后粘贴 | 需要先有那个工具 |

**小贴士**：有些站点（吾爱破解）要求 **Cookie 与 UA 配对**，UA 不一致会被 WAF 拦；Cookie 会过期，
到期后日志提示「登录已失效」，重新复制粘贴一次即可。

## 常见问题 FAQ

**Q：报「已签到」，去网站点签到却还能领积分？**
根因是站点有**两个长得一样的签到**（真发生在糊涂鳄：首页悬浮窗 `user_qiandao` 给 5 晶石，会员中心
`xb_user_qiandao` 只给 1 积分）。面板现在打真接口，而且从首页按钮真正绑定的代码里去发现它，主题升级也不易失效。

**Q：网站反馈里那行字是谁说的？**
网站自己回的原文，面板不改写。判成功会结合站点状态页/首页核对；读不清时如实写「未能复查」或「结果未知」。

**Q：面板说「遇到人机验证」，可我在浏览器里明明是登录着的？**
人机验证（Cloudflare / 网宿 WAF）判定的是**出口 IP**，不是你的账号。云端出口是机房 IP 必被拦 ——
把那个账号切成 **🌐 本地网络**（或等扩展在线后自动切）。

**Q：扩展离线 / 本地网络不可用？**
检查：扩展是否装着并启用、弹窗里地址与 Key 对不对（点「面板连接检查」）、`workers.dev` 在国内能否打开
（不行就绑自定义域名）。离线时本地网络账号记为跳过，不会误报失败。

**Q：定时到点了却没跑？**
签到时间判定是「到点后执行」，且：执行过并**成功**当天不再跑；**失败/结果未知**隔 15 分钟自动补一次；
超过 6 小时的补跑窗口（比如晚上才部署）就等下一个自然日 —— 想立刻签就点「执行」。
另外浏览器工单（吾爱这类）**只在到点后才下发**：以前它只看「今天还没签上」，于是零点一过就被自动签，
看起来像「吾爱不跟随全局时间」，现在跟随全局（或该账号自己的）时间。

**Q：吾爱这类论坛，面板怎么判断「今天签没签」？**
先看首页/顶栏的打卡入口状态（「打卡签到」= 未签，「签到完毕」= 已签），已签就直接结束，不打签到接口；
打完再回读一次核对。两边对不上就如实报没签上。

## 数据与安全

- **管理密码**：PBKDF2-SHA256（10 万次迭代）加盐哈希存 D1，不存明文。
- **账号凭据**（Cookie / 密码 / token）：AES-GCM 加密后存 D1；密钥来自 `ENCRYPT_KEY` Secret。
- **会话**：服务端 session + HttpOnly + Secure + SameSite，7 天过期；改密码会把所有已登录浏览器踢下线。
- **扩展接口**：独立 API Key 鉴权，支持 HMAC 签名 + 防重放。
- **出站请求**：只允许公网 http(s)，**每一跳重定向都重新过闸门**；内网 / 回环 / 云元数据地址一律拒绝；
  本地中继的方法有白名单、会清掉 Host/Connection/Content-Length 等头并拦 CRLF 注入，响应体超过 4MB 放弃。
- **扩展权限边界**：只读你**当前正在看的那一个网站**的 Cookie，你不点按钮就不上传；不执行面板下发的任何脚本字符串；
  导航只在自己开的后台标签页里；面板地址非 https（本机调试除外）直接拒绝。
- **推送密钥**：读取时脱敏，留空提交即保留旧值。

完整清单与漏洞上报方式见 [SECURITY.md](../SECURITY.md)。请只签**你自己的**账号。

## 更新 / 备份 / 发版

**更新面板**：拿到新代码后在项目目录重新部署，账号数据不受影响。

```bash
npx wrangler@latest deploy
```

> 更新里若含扩展改动，部署完**再去面板下载一次扩展并重新加载**（扩展源码内嵌在面板里，必须重新下载才会更新）。

**备份数据库**：

```bash
npx wrangler@latest d1 export daily-checkin-panel --remote --output backup.sql
```

> 备份里是**加密后**的凭据；`ENCRYPT_KEY` 若是自动生成的，恢复时要用同一个 D1 才解得开。

**开发与发版**（不需要看懂也能用，一条命令全包）：

```bash
node tools/verify.mjs          # 自检：语法 + HTML 配对 + DOM 引用 + 全部单测（CI 跑的就是它）
node tools/pack-zip.mjs        # 打发布包到 release/，带文件数、大小、SHA-256
node tools/release.mjs minor   # 发版：自检 → 升版本号 → 写 CHANGELOG → 打发布包，并提示 git 命令
node deploy.mjs --check        # 部署前体检（GitHub Actions 的部署检查也是它）
```

- 版本号唯一真源是 `src/version.js`（测试会断言 `package.json` 与之一致）；改动记进 [CHANGELOG.md](../CHANGELOG.md)。
- `.github/workflows/`：`ci.yml` 每次推送/PR 跑自检；`release.yml` 推 `v*` tag 自动复跑自检、
  校验 tag 与版本号一致、把 zip 传成 GitHub Release；`deploy.yml` 是**可选**的手动部署（默认只 dry-run）。

## 项目结构 / 自己加站点

```
src/
  index.js      路由 + API + Cron 入口          runner.js     执行引擎（遍历 / 写日志 / 推送）
  db.js         表结构 + 版本化迁移             crypto.js     密码哈希 / 凭据加解密
  schedule.js   签到时间与时区判定              notify.js     Telegram / Bark / Webhook
  probe.js      签到接口自动探测                ext-zip.js    动态生成扩展 zip（注入面板地址）
  community.js  社区配置校验 / 导入导出         version.js    版本号（唯一真源）
  lib/          web.js（模拟浏览器请求）· relay.js（中继）· signals.js（反馈识别）·
                net-guard.js（出站闸门）· ext-auth.js（扩展鉴权）· net-check.js（网络连通性）
  sites/        各站点模块 + index.js 注册表（http.js 是自定义 HTTP / 社区配置的引擎）
public/         index.html（后台 SPA）· ext-src/（扩展源文件，改完要重新生成 ext-files.js）
community/      社区站点配置（JSON）+ 模板 + 索引
tools/          verify / pack-zip / release / gen-ext-files / check-html …
test/           零依赖单测：node test/xxx.test.mjs
```

**加站点两条路**：

- **不改代码**：自定义 HTTP 录一遍 → 导出社区配置 → 自己用或分享（见上文）。适合绝大多数「带 Cookie 打一两个接口」的站。
- **要写代码**（人机验证、签名、多步浏览器流程）：在 `src/sites/` 新建文件（照 `nodeseek.js` 抄），
  在 `src/sites/index.js` 的 `SITES` 里注册，然后跑 `node tools/verify.mjs` 再部署 —— 网页表单会自动出现这个站点。

```js
export const mysite = {
  id: 'mysite', name: '我的站点', desc: '一句话说明',
  fields: [{ key: 'cookie', label: 'Cookie', type: 'textarea', required: true }],
  tips: '给用户的提示',
  async run(creds, ctx) {  // ctx: { env, db, account, meta }；meta 可读写并自动持久化
    return { ok: true, message: '签到成功' };
  },
};
```

**字段约定**（扩展「一键复制」粘贴过来时，符合约定的字段会自动填，不用用户手敲）：

| 字段 key | 含义 | 自动填入的内容 |
|---|---|---|
| `cookie` | 登录 Cookie | 扩展抓到的完整 Cookie（含 HttpOnly） |
| `user_agent` | User-Agent | 扩展抓到的页面真实 UA（吾爱这类要求 Cookie 与 UA 配对的站必须声明） |
| `page_url` | 采集时的页面地址 | 扩展抓到的**完整页面 URL**（如 `https://www.v2ex.com/mission/daily`）。站点校验 Referer / Origin 时用它拼 |
| `site_url` | 站点地址 | 从粘贴的域名推出来（如 `https://hutue.cn`，一模块管多个域名时用） |
| localStorage 里的键 | 如 akile 的 `token` | 扩展附带的 localStorage 里同名的值 |

扩展每次采集的凭据包 = `{ domain, pageUrl, userAgent, cookies, cookieList, localStorage }`：
`domain` 是裸域名（站点匹配、跨域校验用），`pageUrl` 是当时页面的完整地址
（Referer / Origin 校验用），`cookieList` 是逐条分解（含 HttpOnly / 过期时间，
面板上展示用）。以后接「Cookie + UA + Referer 三件套校验」的特殊站点时，
声明 `page_url` 字段即可，采集链路不用再改。

**改扩展**：改 `public/ext-src/` → 跑 `node tools/gen-ext-files.mjs` 重新生成 `src/ext-files.js` → 部署。**否则用户下载到的还是旧版扩展。**
